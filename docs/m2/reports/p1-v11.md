## Decisions I made that the brief left open (manager: overrule any)

| # | Decision | Why |
|---|---|---|
| D1 | A settings op is **all or nothing** (one stale key refuses the whole op), and it **can't carry elements** (`bad-op`) | Replay runs no checks, so the logged op must be exactly the op that was sent. Keeping elements out means a soft refusal never takes elements with it |
| D2 | **One settings op in flight per (stream, key)** per client. Later changes wait in the overlay and are stamped with a base when sent. If the first op is refused, the waiting changes to that key are dropped with it, and the app is told | The second op's base isn't known until the first op settles |
| D3 | `stale-setting` is checked **after the op-id table** (a resend gets its `ack`), against the **speculative** `appSeq`, and is held like other refusals | Same as the other checks. Without this, a resend would be refused by its own `seq` |
| D4 | **Retry only** once the client's confirmed `appSeq` has passed the refused base | Stops a retry loop against an entry the client hasn't applied yet |
| D5 | **Epoch lives in the board's lease record in the Store** (`Store.openEpoch` is an atomic, durable increment that runs before the first `welcome`), **not in the checkpoint** | Checkpoints are written asynchronously, and the one with the highest `seq` wins. A rebuild that writes none, or that falls back past a bad one, would reuse an epoch |
| D6 | Viewers' `welcome.room.epoch` is the gateway's latest known epoch: from the room's heartbeat `{seq, epoch}`, or from a Store read. It may lag during a rebuild | Viewers never reach the room |
| D7 | Client: a wrong `room.board` means close and reconnect (a failed attempt). The epoch checks run **only on a room-built (writer's) `welcome`**: an epoch lower than one it has seen means close and reconnect; a higher epoch with `welcome.seq` below the client's applied `seq` means resync. A viewer only records the epoch | A gateway-built (viewer's) `welcome` may lag, and reacting to it could loop or resync for nothing. A seq regression on a writer's `welcome` from a new epoch means the Store lost acked entries (a known limit) |
| D13 | `Replica.local()` **splits** a mixed local change into two ops: elements first, then settings | Otherwise an honest client would get `bad-op` and resync |
| D8 | Seeding: an element the room **has**, more than 1,000 below the file's version, is **held back with a warning**, not sent | That is what drawh's `push()` does today (proposal patch, line 364) |
| D9 | seamv **M2: per-connection gateway bucket, and at most 8 writer connections per (user, board) per gateway**. A ninth `hello` gets `limit` (no `id`) and is closed; the client backs off | This is the verifier's first fix. It also bounds the G × rate known limit. The number 8 is my pick |
| D10 | seamv **L2: append timeout 4 s** (two appends = 8 s, inside the client's 10 s) | This is the verifier's first fix |
| D11 | seamv **L1:** the client codec writes `{"t":"op","id":…` first, and the gateway names that `id` in frame-level refusals. I did not adopt the verifier's "refused twice" fallback | The gateway already reads the id from the head (`server/gateway.js:77,393`). With the id, rule 5 applies directly |
| D12 | `@googlemail.com` is **not** treated as gmail (never authoritative) | Conservative. Such a user can still use a grant or a share link |

## Where frozen code disagrees with the spec now

- `envelope.js:22` `MAX_OP_CHARS` (chars, not bytes); `:46` `APPEND_TIMEOUT_MS = 5000`; `:71` `MAX_OP_DEPTH = 64`.
- `room.js`/`replica.js`: no `appBase`, no `stale-setting`, no `welcome.room`, no `keepVersions`. `local()`
  always normalizes, so today an import can't send versions unchanged.
- `server/gateway.js` (main repo, untracked; not in the worktree): bucket per (user, board); no connection cap.
  `nestedDeeperThan(…, 64)` on the frame matches the spec.
- `server/room-host.js` publishes catch-up on `.gw` (p4-natss3's note).
- Postgres adapters run `CREATE … IF NOT EXISTS` at start (p4-pgv M1).
- The drawh proposal patch sends settings without a base. It goes through `local()`, but **its own protocol copy
  is the v0 one** (`local(stream, op, { transient = false })`, patch lines 1724 and 2082), which doesn't normalize.
  That is why its tests see versions kept. Once drawh takes the phase-2 protocol, `local()` normalizes everything,
  so drawh needs `keepVersions` (a kept-version op is also exempt from `restampAll()`) or its seeding rule breaks.
